Module used to manage the backport of a pull request to another branch.

### Functionality Details

This module automates the process of backporting pull requests to stabilization or other branches. It:

- **Label Management**: Updates labels on pull requests based on the [`SECURITY.md`](https://github.com/camptocamp/c2cciutils/wiki/SECURITY.md) file.
- **Workflow Validation**: Fails workflows if the `BACKPORT_TODO` file exists, ensuring that unresolved backport tasks are addressed.
- **Backport Pull Request Creation**: Automatically creates backport pull requests to specified branches. A rerun of the job rebuilds the `ghci/backport/<number>-to-<branch>` branch from the target branch and updates the already opened pull request, but only if the head commit of that branch was committed by the application: a branch whose `BACKPORT_TODO` conflicts were resolved and pushed by a human contributor is never overwritten.
- **Body Reset On Resolution**: When a backport has conflicts, the pull request body contains the resolution instructions and a `BACKPORT_TODO` file is committed. Once the conflicts are resolved and the `BACKPORT_TODO` file removed from the branch, the stale instructions are replaced by the clean `Backport of #<number> to <branch>` message followed by a `Conflicts resolved manually` note. Only a body generated by the application is rewritten, a customized body is never touched.
- **Label Copy**: Copies the labels of the source pull request to the backport pull request, so that the changelog of the target branch classifies it like the original one. The `backport <branch>` labels are excluded to not request a backport of the backport pull request.

### Configuration Options

You can configure the backport module using the `.github/ghci.yaml` file or a similar configuration file. Example options include:

[Configuration reference](https://github.com/camptocamp/github-app-geo-project/blob/master/BACKPORT-CONFIG.md).

### Usage Notes

- Ensure the `SECURITY.md` file is up-to-date to accurately reflect stabilization branches.
- Use the `BACKPORT_TODO` file to track unresolved backport tasks.
- Regularly review backport pull requests to ensure they meet project standards.
